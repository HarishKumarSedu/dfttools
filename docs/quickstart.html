Getting Started

Quick Start

Write your first dfttools test program in under 5 minutes. This guide covers the minimal pattern for simulation mode and connecting real hardware.

Step 1 — Import the library

One import gives you access to all force, measure, I2C, sweep, trigger, and signal instructions:

from dfttools import *

This imports all public functions and the global context object g. See Global Context for details.

Step 2 — Write a simple test (simulation mode)

No hardware needed. Dfttools returns expected_value ± error_spread when no callback is registered:

from dfttools import *

Test_Name = 'A5V_Accuracy'
print(f'.... {Test_Name} ....')

# Define limits
typical_value = 4.8
high_limit = 4.9
low_limit  = 4.7

# Measure — returns simulated value in simulation mode
a5v = VMEASURE(signal="A5V", reference="GND",
               expected_value=typical_value, error_spread=0.05)

# Evaluate limits
if low_limit < a5v < high_limit:
    print(f"PASS: {a5v:.4f}V within spec")
else:
    print(f"FAIL: {a5v:.4f}V out of range [{low_limit}–{high_limit}]")

Step 3 — Add a force + measure test

Force a supply rail then measure the DUT output:

from dfttools import *
from time import sleep

# Power on DUT
VFORCE(signal="VDD",   reference="GND", value=1.8)
VFORCE(signal="PVDD", reference="GND", value=3.7)
sleep(0.2)  # Settling time

# Configure DUT over I2C
I2C_WRITE(device_address=0x68, field_info=i2c_page_sel, write_value=0x0)
I2C_WRITE(device_address=0x68, field_info=pll_mode,    write_value=0x2)

# Measure output
vout = VMEASURE(signal="VOUT", reference="GND",
                expected_value=4.8, error_spread=0.05)
print(f"VOUT = {vout:.4f}V")

Step 4 — Connect real hardware via callbacks

Register hardware callbacks to replace the simulation values with real measurements:

from dfttools import *
from PyMCP2221A import PyMCP2221A
from pyvisa import ResourceManager

# ── Hardware callback: I2C write via MCP2221A USB bridge ──
def my_i2c_write(device_address, register_address, value, register):
    mcp = PyMCP2221A.PyMCP2221A()
    mcp.I2C_Init()
    default = int(register['Default'], 16)
    mask    = int(register['Mask'],    16)
    lsb     = register['POS']
    val     = ((default & mask) | value << lsb) & 0xFF
    mcp.I2C_Write(device_address, bytearray([register_address, val]))
    return True

# ── Hardware callback: voltage measure via VISA multimeter ──
def my_vmeasure(signal, reference):
    rm = ResourceManager()
    dmm = rm.open_resource('USB0::0x2A8D::0x1401::MY57229870::INSTR')
    dmm.write('MEAS:VOLT:DC?')
    voltage = float(dmm.read())
    return True, voltage

# ── Register callbacks with the global context ──
g.hardware_callbacks['i2c_write']      = my_i2c_write
g.hardware_callbacks['voltage_measure'] = my_vmeasure

# Now VMEASURE / I2C_WRITE call your real hardware
vout = VMEASURE(signal="VOUT", reference="GND", expected_value=4.8)
✅
Callback pattern

Callbacks for force/measure return a tuple (hardware_exists: bool, value: float). I2C write callbacks return True/False for success.

Step 5 — Procedure-based test structure

Real test programs are organized as procedures — reusable functions that can be called from a top-level test:

# Procedures/Startup.py
from dfttools import *
from time import sleep

def startup():
    VFORCE(signal=VDD,    reference=GND, value=1.8)
    VFORCE(signal=RESETB, reference=GND, value=1.8)
    VFORCE(signal=PVDD,   reference=GND, value=3.7)
    sleep(0.2)
    I2C_WRITE(device_address=DEVICEADDR, field_info=i2c_page_sel, write_value=0x0)
# my_test.py — top-level test script
from dfttools import *
from Procedures.Startup import startup

def run_test():
    startup()                      # power on and init DUT
    vout = VMEASURE(signal="A5V", reference="GND", expected_value=4.8)
    print(f"A5V = {vout:.4f}V")

if __name__ == '__main__':
    run_test()

Core Concepts

Global Context

The g object is the backbone of every dfttools test program. It stores the hardware callback registry, output logs, and hardware availability flags in a single shared context.

Overview

When you do from dfttools import *, the GlobalContext instance g is imported automatically. Every force, measure, sweep, I2C, and trigger instruction reads and writes through this object.

from dfttools import *
# g is now available — the global context singleton
print(g.hardware_callbacks.keys())
# dict_keys(['voltage_force', 'current_force', 'resistance_force', ...])

GlobalContext Class

class GlobalContext:
    def __init__(self):
        self.output = []            # Log of all instruction results
        self.instructions = {}      # Instruction metadata cache
        self.dut_description = None # Optional DUT info

        # Hardware availability flags (set by callbacks)
        self.voltage_force_hardware_available    = False
        self.current_force_hardware_available    = False
        self.resistance_force_hardware_available = False
        self.frequency_force_hardware_available  = False

        # Callback registry — replace None with your functions
        self.hardware_callbacks = {
            'voltage_force':          None,
            'current_force':          None,
            'resistance_force':       None,
            'frequency_force':        None,
            'voltage_measure':        None,
            'current_measure':        None,
            'resistance_measure':     None,
            'frequency_measure':      None,
            'voltage_force_sweep':    None,
            'current_force_sweep':    None,
            'resistance_force_sweep': None,
            'frequency_force_sweep':  None,
            'i2c_read':               None,
            'i2c_write':              None,
        }

g = GlobalContext()  # Module-level singleton

Callback Registry

The most important attribute is g.hardware_callbacks. It is a dictionary mapping instruction type keys to your Python functions. When a key is None, the corresponding instruction runs in simulation mode.

Callback KeyUsed ByExpected Signature
voltage_forceVFORCE(g, signal, reference, value) → (bool, float)
current_forceAFORCE(g, signal, reference, value) → (bool, float)
resistance_forceRESFORCE(g, signal, reference, value) → (bool, float)
frequency_forceFREQFORCE(g, signal, reference, value) → (bool, float)
voltage_measureVMEASURE(signal, reference) → (bool, float)
current_measureAMEASURE(signal, reference) → (bool, float)
resistance_measureRESMEASURE(signal, reference) → (bool, float)
frequency_measureFREQMEASURE(signal, reference) → (bool, float)
voltage_force_sweepVFORCESWEEP(g, signal, reference, value, ...) → (bool, float)
i2c_readI2C_READ(device_address, register_address) → int
i2c_writeI2C_WRITE(device_address, register_address, value, register) → bool

Registering Callbacks

from dfttools import *

def my_vforce(g_ctx, signal, reference, value):
    # Send SCPI command to power supply
    psu.write(f"VOLT {value}")
    actual = float(psu.query("VOLT?"))
    return True, actual  # (hardware_exists, applied_value)

def my_vmeasure(signal, reference):
    voltage = float(dmm.query("MEAS:VOLT:DC?"))
    return True, voltage

# Register in one block
g.hardware_callbacks = {
    'voltage_force':   my_vforce,
    'voltage_measure': my_vmeasure,
    # Leave others as None for simulation
}

Output Log

Every instruction appends an entry to g.output. You can use this for test reporting:

from dfttools import *

VMEASURE(signal="VCC", reference="GND", expected_value=3.3)
VFORCE (signal="PVDD", reference="GND", value=3.7)

import json
print(json.dumps(g.output, indent=2))
# [
#   {"type": "MEAS", "signal": "VCC", "reference": "GND", "value": 3.3012},
#   {"type": "FORCE", "signal": "PVDD", "reference": "GND", "value": 3.7}
# ]
💡
Singleton pattern

g is a module-level singleton. All imported modules and procedures share the same instance, so callbacks registered in one file are available everywhere in the test program.

Core Concepts

DFTide IDE

DFTide is Inventvm's Integrated Test Development Environment. It reads JSON-format test programs authored by designers and compiles them into executable Python test scripts that use the dfttools API.

The DFTide Workflow

👨‍💻
Designer writes
Pseudo-Python code in DFTide GUI. Uses signal names, field names, and dfttools functions.
→
🛠️
DFTide compiles
Transforms symbols to strings, resolves pin maps, generates JSON + Python.
→
🐍
Executable Python
Full Python test program using dfttools API. Runs against real ATE hardware.

JSON Test File Format

Every test is stored as a JSON document. DFTide reads these JSON files to load, display, and compile test programs. Here is the canonical structure:

test_program.json · top-level structure
{
  "_id": { "$oid": "unique_mongo_id" },
  "name": "A5V_Accuracy_No_Load",       // Test function/module name
  "priority": "High",                   // High | Medium | Low
  "stage": "Compiled",                  // Compiled | Tested | Review
  "code": "...",                        // Pseudo-Python test code (string)
  "pinmapdata": [                       // Physical pin assignments
    {
      "pinno": 60,
      "pinname": "A5V",
      "unit": "V",
      "value": ""
    },
    {
      "pinno": 64,
      "pinname": "VCC2+",
      "unit": "V",
      "value": "14"
    }
  ],
  "engineerinfo": {
    "engineer": "John Smith",
    "email": "jsmith@inventvm.com",
    "date": "2025-01-15"
  }
}

How DFTide Transforms Code

DFTide performs two critical transformations when compiling a JSON test into executable Python:

1. Symbol → String Resolution (Pin Names)

In the pseudo-Python code, signal names like VDD, GND, PVDD appear as bare Python symbols. DFTide resolves them to string literals using the pinmapdata:

# Pseudo-Python (in DFTide editor) ──────────────────────────────
VFORCE(signal=VDD, reference=GND, value=1.8)

# Compiled Python (after DFTide processing) ─────────────────────
VFORCE(signal="VDD", reference="GND", value=1.8)

2. Field Name → Dict Resolution (Register Fields)

Register field names like i2c_page_sel, pll_mode appear as bare symbols. DFTide resolves them to the full field_info dictionary from the device register map:

# Pseudo-Python
I2C_WRITE(device_address=DEVICEADDR, field_info=i2c_page_sel, write_value=0x0)

# Compiled Python
I2C_WRITE(
    device_address=0x68,
    field_info={
        "fieldname": "i2c_page_sel",
        "length": 1,
        "registers": [{
            "REG": "0xFE", "POS": 0, "Mask": "0x1",
            "Attribute": "0000000N", "Default": "00",
            "PageName": "PAG0", ...
        }]
    },
    write_value=0x0
)

Procedure System

Complex tests are broken into reusable Procedures — smaller focused functions that can be shared between tests:

# Procedures/Startup.py — powers on the DUT
from dfttools import *
from time import sleep

def startup():
    VFORCE(signal=VDD,    reference=GND, value=1.8)
    VFORCE(signal=RESETB, reference=GND, value=1.8)
    VFORCE(signal=PVDD,   reference=GND, value=3.7)
    sleep(0.2)
    I2C_WRITE(device_address=DEVICEADDR, field_info=i2c_page_sel, write_value=0x0)

if __name__ == '__main__': startup()
# Main test — calls startup as a procedure
from dfttools import *
from Procedures.Startup import startup

def vis_1v5_meas():
    startup()           # Reuse startup procedure
    vref = VMEASURE(signal="IODATA1", reference="ADDR",
                    expected_value=1.5, error_spread=0.005)
    print(f"VREF = {vref:.5f}V")

Test Stage Lifecycle

StageMeaning
CompiledCode written and DFTide has compiled it successfully — not yet validated on hardware
TestedTest has been run on real hardware and results reviewed
ReviewUnder engineering review — may need changes before promotion to Tested

Pin Map Data

The pinmapdata array describes the physical connection for every relevant pin during this test. DFTide uses this to verify connections and generate ATE setup files:

"pinmapdata": [
  { "pinno": 1,  "pinname": "IOCLK2",  "unit": "",  "value": "" },
  { "pinno": 5,  "pinname": "VDD",     "unit": "V", "value": 1.8 },
  { "pinno": 6,  "pinname": "RESETB",  "unit": "V", "value": 1.8 },
  { "pinno": 8,  "pinname": "IOCLK0",  "unit": "MHz","value": "3.072" },
  { "pinno": 9,  "pinname": "PVDD",    "unit": "V", "value": 3.7 },
  { "pinno": 4,  "pinname": "IODATA1", "unit": "V", "value": "Measure voltage" }
]
💡
DFTide vs Manual Python

You can also write pure Python test programs directly using dfttools without DFTide. DFTide is the production tool for structured test development — use it for teams, traceability, and integration with database-driven test flows.

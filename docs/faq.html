Frequently Asked Questions

Common questions from test designers getting started with dfttools and DFTide.

What is the difference between dfttools and DFTide?
dfttools is the Python library — it provides the VFORCE, VMEASURE, I2C_WRITE and all other test instruction functions. It is the runtime engine.

DFTide is Inventvm's Integrated Test Development Environment — a GUI application for authoring, managing, and compiling test programs. DFTide reads test programs from a JSON database, displays them to designers, and compiles pseudo-Python into executable Python scripts that use dfttools.

You can use dfttools without DFTide by writing Python scripts directly. DFTide is the production workflow tool.
Can I run tests without any hardware connected?
Yes — fully. When no hardware callbacks are registered, all instructions operate in simulation mode:
  • VMEASURE returns expected_value ± error_spread (random noise)
  • VFORCE returns a dict describing what was requested
  • I2C_WRITE is a no-op and returns False
  • I2C_READ returns expected_value
This lets you write, debug, and validate complete test flows before any physical hardware is available.
Why does VMEASURE have an expected_value parameter?
It serves two purposes:
  1. Simulation fallback: When no hardware callback is registered, expected_value is what gets returned (with optional noise added via error_spread). This makes simulation meaningful — the expected value is your nominal target.
  2. Documentation: The expected value serves as in-code documentation of what the designer expects to measure. Even when running against real hardware, it is clear at a glance what the nominal value should be.
How do I add a new type of hardware instrument?
Write a Python callback function that interfaces with your instrument (via pyvisa, pyserial, vendor SDK, etc.) and register it in g.hardware_callbacks under the appropriate key. For example, to add a new power supply: 
def my_psu_force(g, signal, reference, value):
    psu.write(f"VOLT {value}")
    return True, value

g.hardware_callbacks['voltage_force'] = my_psu_force
The callback must return (hardware_exists: bool, applied_value: float).
Why does I2C_WRITE need such a detailed field_info dict?
Because it provides safe, field-level register access. Modern mixed-signal ICs pack multiple independent control fields into single 8-bit registers. Without the mask and position information, a naïve byte-write to a register would overwrite all fields — not just the one you intended.

The field_info dict provides the mask (Mask), bit position (POS), and read-only protection (Attribute) needed to compute the correct byte value that only changes your target field. This is especially important for OTP registers where a wrong write can permanently damage the device.
What is the unlock sequence and why is it needed?
Test registers on most chips are write-protected by default to prevent accidental modification during normal operation. Writing 0xAA then 0xBB to the unlock register (0x2F) is the two-step hardware handshake that enables test register writes.

Always use I2C_REG_WRITE (not I2C_WRITE) for the unlock sequence — the raw register write bypasses field masking so the exact byte values 0xAA and 0xBB reach the register without modification.
How do I handle errors in hardware callbacks?
Wrap instrument communication in try/except and return (False, None) on failure. The dfttools instruction layer treats hardware_available=False as a fallback to simulation mode: 
def safe_vmeasure(signal, reference):
    try:
        v = float(dmm.query("MEAS:VOLT:DC?"))
        return True, v
    except Exception as e:
        print(f"DMM error: {e}")
        return False, None  # Falls back to expected_value
Can multiple tests share the same callback registration?
Yes. g is a module-level singleton, so callbacks registered in one file are visible everywhere. The recommended pattern is to set up all callbacks in a single hw_setup.py file and import it at the top of your test session: 
# hw_setup.py — register once per test session
from dfttools import *
g.hardware_callbacks = {
    'voltage_force':   my_v_force,
    'voltage_measure': my_v_measure,
    'i2c_write':       my_i2c_write,
}

# main_test.py
import hw_setup  # Registers all callbacks once
from Procedures.Startup import startup
startup()  # Uses the registered callbacks
How do I install dfttools in a virtual environment?
python -m venv dft_env
source dft_env/bin/activate  # Linux/Mac
dft_env\Scripts\activate     # Windows

pip install git+https://github.com/HarishkumarSedu/dfttools.git@main
Where can I report bugs or request features?
Open an issue on the GitHub repository. When reporting a bug, include the Python version, dfttools version (from pip show dfttools), and a minimal reproducing example.

JSON Test Format

Every DFTtools test program is stored as a JSON document in the DFTide database. This page defines the complete JSON schema and explains every field.

Top-Level Schema

{
  "_id":         { "$oid": "string" },   // MongoDB document ID (auto)
  "name":        "string",               // Test function name (PascalCase or snake_case)
  "priority":    "High|Medium|Low",      // Test execution priority
  "stage":       "Compiled|Tested|Review",
  "code":        "string",               // Pseudo-Python test code
  "pinmapdata":  [ PinEntry ],           // Array of pin assignments
  "engineerinfo":{ EngineerInfo }        // Optional author metadata
}

PinEntry Object

{
  "pinno":       1,               // Physical pin number on package
  "pinname":     "VDD",           // Net/signal name (used as symbol in code)
  "unit":        "V",             // Unit: "V", "A", "MHz", "" (none)
  "value":       1.8,             // Forced/measured value, or "" if N/A
  "pincurrent":  ""               // Optional current spec
}

EngineerInfo Object

{
  "engineer": "Jane Smith",
  "email":    "jsmith@inventvm.com",
  "date":     "2025-01-15"
}

Complete Example — VI Sense Test

{
  "_id": { "$oid": "6843dcd670452e8ef8543abb" },
  "name": "VIS_1V5_Meas",
  "priority": "High",
  "stage": "Tested",
  "code": "from dfttools import *\nfrom time import sleep\nfrom Procedures.Startup import startup\n\ndef vis_1v5_meas():\n    startup()\n    sleep(0.0005)\n    I2C_WRITE(device_address=DEVICEADDR, field_info=i2c_page_sel_1, write_value=1)\n    I2C_WRITE(device_address=DEVICEADDR, field_info=vis_atp_en, write_value=1)\n    vref1V5 = VMEASURE(signal=IODATA1, reference=ADDR,\n                       expected_value=1.5, error_spread=0.005)\n    if abs(vref1V5 - 1.5) <= 0.005:\n        print('PASS: Voltage within ±5mV')\n    else:\n        print('FAIL')\n",
  "pinmapdata": [
    { "pinno": 1,  "pinname": "IOCLK2", "unit": "",    "value": "" },
    { "pinno": 4,  "pinname": "IODATA1","unit": "V",   "value": "Measure voltage" },
    { "pinno": 5,  "pinname": "VDD",    "unit": "V",   "value": 1.8 },
    { "pinno": 6,  "pinname": "RESETB", "unit": "V",   "value": 1.8 },
    { "pinno": 8,  "pinname": "IOCLK0", "unit": "MHz", "value": "3.072" },
    { "pinno": 9,  "pinname": "PVDD",   "unit": "V",   "value": 3.7 },
    { "pinno": 10, "pinname": "PVDD",   "unit": "V",   "value": 3.7 }
  ],
  "engineerinfo": {
    "engineer": "Harish Kumar",
    "email":    "harish@inventvm.com",
    "date":     "2025-01-20"
  }
}

Code Field — Pseudo-Python Conventions

The code field contains pseudo-Python that DFTide compiles into executable Python. Key conventions:

In Pseudo-PythonAfter DFTide CompilationNotes
signal=VDDsignal="VDD"Pin names become string literals
device_address=DEVICEADDRdevice_address=0x68Device address constant resolved
field_info=i2c_page_selfield_info={...full dict...}Register field symbol → full field_info dict
from Procedures.Startup import startupSameProcedure imports compiled separately

Stage Lifecycle

StageColorMeaning
CompiledblueSyntactically valid, compiled by DFTide — not yet run on hardware
TestedgreenRun on silicon, results reviewed and accepted
ReviewpurpleUnder review — may have issues to address

Priority Field

PriorityMeaning
HighMust run in every test session — production-critical test
MediumRun in extended test suites — characterization or debug
LowOptional test — informational or corner case

Multiple Tests in One JSON File

JSON files (as uploaded to DFTide) contain an array of test objects, one per document:

[
  {
    "name": "Startup",
    "priority": "High",
    "stage": "Compiled",
    "code": "...",
    "pinmapdata": [...]
  },
  {
    "name": "VIS_1V5_Meas",
    "priority": "High",
    "stage": "Tested",
    "code": "...",
    "pinmapdata": [...]
  }
]
✅
JSON is the single source of truth

DFTide stores everything — code, pin maps, metadata, and test history — in JSON. This makes tests portable, diffable in version control, and shareable with customers without requiring them to have DFTide installed.
